# WirePack — структура данных и формат проекта

**Версия:** 0.1  
**Статус:** Черновик

## 1. Общие положения

Для сохранения и открытия проектов WirePack используется формат JSON.

Формат должен обеспечивать сохранение исходных данных и результатов расчёта.

Структура данных проекта не должна зависеть от внутренней реализации пользовательского интерфейса и геометрического ядра.

## 2. Структура проекта

Проект WirePack содержит следующие данные:

- Информацию о формате и версии проекта.
- Исходные данные проводов.
- Результаты расчёта, если расчёт выполнялся.

## 3. Исходные данные проводов

Провода хранятся группами.

Каждая группа содержит:

- Наружный диаметр провода в миллиметрах.
- Количество проводов.

При загрузке проекта количество и диаметры проводов должны проверяться на корректность.

## 4. Результаты расчёта

Каждый найденный вариант компоновки содержит:

- Уникальный идентификатор варианта.
- Внутренний диаметр защитной трубки в миллиметрах.
- Координаты центра защитной трубки в миллиметрах.
- Координаты центра каждого провода.
- Наружный диаметр каждого провода.

Координаты задаются в миллиметрах в единой системе координат.

Для каждого варианта должны сохраняться все данные, необходимые для повторного отображения компоновки без повторного запуска оптимизации.

Сохранённые центр и диаметр защитной трубки должны соответствовать минимальной охватывающей окружности компоновки с учётом численного допуска. При открытии проекта они пересчитываются по координатам проводов и проверяются.

## 5. Версионирование

Файл проекта должен содержать номер версии формата данных.

При открытии проекта программа должна проверять совместимость версии файла с поддерживаемой версией формата.

Структура должна допускать развитие формата в будущих версиях приложения.

## 6. Проверка данных

При открытии проекта необходимо проверять:

- Наличие обязательных полей.
- Корректность диаметров и количества проводов.
- Корректность координат и размеров сохранённых вариантов.
- Соответствие результатов расчёта исходному набору проводов.

Некорректные данные не должны приводить к аварийному завершению программы.

При изменении исходных данных после расчёта сохранённые результаты считаются устаревшими и не отображаются как актуальные. Конкретный способ обработки устаревших результатов (очистка или явная пометка) определяется при реализации интерфейса.

## 7. Сохранение и открытие

Программа должна поддерживать:

- Создание нового проекта.
- Сохранение проекта в JSON-файл.
- Открытие ранее сохранённого проекта.
- Повторное отображение сохранённых результатов расчёта.

Сохранение проекта не должно изменять исходные данные или геометрию найденных вариантов.
