# WirePack — структура данных и формат проекта

**Версия:** 0.2
**Статус:** Актуальное

## 1. Общие положения

Для сохранения и открытия проектов WirePack используется JSON на основе `System.Text.Json`.

Файл проекта имеет расширение `.wpack`. Внутреннее содержимое файла — обычный JSON без архивирования и шифрования.

Структура данных проекта не зависит от пользовательского интерфейса и внутренних структур геометрического ядра.

## 2. Структура проекта

Проект WirePack содержит:

- версию схемы данных (`schemaVersion`);
- исходные группы проводов;
- результаты расчёта, если расчёт выполнялся.

Пример:

```json
{
  "schemaVersion": 1,
  "wireGroups": [
    {
      "id": "g1",
      "diameter": 2.0,
      "count": 3,
      "color": "#FF3B82F6"
    }
  ],
  "variants": [
    {
      "id": "v1",
      "tubeDiameter": 7.2,
      "tubeCenter": { "x": 0.1, "y": -0.2 },
      "fillFactor": 0.71,
      "wires": [
        {
          "groupId": "g1",
          "diameter": 2.0,
          "center": { "x": 0.0, "y": 0.0 }
        }
      ]
    }
  ]
}
```

## 3. Исходные данные проводов

Провода хранятся группами. Каждая группа содержит:

- уникальный идентификатор `id`;
- наружный диаметр провода в миллиметрах;
- количество проводов;
- цвет группы в формате `#AARRGGBB` или `#RRGGBB`.

Идентификатор группы используется для восстановления принадлежности проводов и цветов после загрузки проекта.

## 4. Результаты расчёта

Каждый найденный вариант компоновки содержит:

- уникальный идентификатор варианта;
- внутренний диаметр защитной трубки в миллиметрах;
- координаты центра защитной трубки;
- коэффициент заполнения;
- провода варианта.

Каждый провод содержит:

- идентификатор исходной группы `groupId`;
- наружный диаметр;
- координаты центра.

Координаты задаются в миллиметрах в единой системе координат.

Коэффициент заполнения сохраняется в файл и при открытии отображается без пересчёта. Повторный расчёт пользователь может выполнить вручную.

Сохранённые центр и диаметр трубки должны соответствовать минимальной охватывающей окружности компоновки с учётом численного допуска. При открытии проекта они пересчитываются по координатам проводов и проверяются.

## 5. Версионирование

Файл проекта содержит свойство `schemaVersion`.

При открытии проверяется совместимость версии с поддерживаемой версией формата. Неподдерживаемая версия приводит к отказу от загрузки без изменения текущего проекта.

Структура допускает расширение в будущих версиях: новые поля добавляются как необязательные, а несовместимые изменения сопровождаются повышением `schemaVersion`.

## 6. Проверка данных

При открытии проекта проверяются:

- наличие обязательных полей;
- поддерживаемая версия схемы;
- уникальность идентификаторов групп и вариантов;
- корректность диаметров, количества и цветов групп;
- корректность координат, размеров и коэффициента заполнения;
- принадлежность каждого провода существующей группе;
- соответствие количества и диаметров проводов исходным группам;
- геометрическая допустимость сохранённых вариантов.

Некорректные данные не приводят к аварийному завершению программы. Ошибки уровня исходных данных делают загрузку неуспешной. Некорректные или устаревшие варианты отбрасываются.

## 7. Сохранение и открытие

Программа поддерживает:

- открытие проекта из файла `.wpack`;
- сохранение проекта;
- сохранение проекта в новый файл;
- повторное отображение сохранённых результатов без запуска оптимизации.

Файловые операции выполняются асинхронно через `ProjectFileService`. Диалоги выбора файла и подтверждения несохранённых изменений вынесены в `IProjectDialogService`.

При наличии несохранённых изменений перед открытием другого проекта или закрытием приложения пользователю предлагается сохранить изменения, отказаться от сохранения или отменить действие.

Сохранение проекта не изменяет исходные данные или геометрию найденных вариантов.
