# AGENTS.md — WirePack

## 1. Общие правила

- Рабочий язык проекта и документации — русский.
- Имена классов, методов, переменных и пространств имён — английские.
- Перед выполнением задачи изучи относящиеся к ней исходники и документацию.
- Не придумывай требования и не выдавай предположения за утверждённые решения.
- Если информации недостаточно, задай вопрос пользователю.
- Не расширяй задачу по собственной инициативе.
- Не усложняй архитектуру без необходимости.

## 2. Источники информации

Приоритет источников:

1. Прямые указания пользователя в текущей задаче.
2. Существующая согласованная документация проекта.
3. Настоящий файл AGENTS.md.
4. Существующий исходный код.

Не считай отсутствующие документы существующими.

Если требования ещё не сформулированы или документация не создана, не пытайся самостоятельно восстановить её содержание. Запроси необходимую информацию у пользователя.

При обнаружении противоречий между источниками сообщи пользователю и дождись решения.

## 3. Порядок выполнения задач

Перед началом каждой задачи:

1. Изучи соответствующие файлы проекта.
2. Определи, какие требования относятся к задаче.
3. Составь краткий план действий.
4. Укажи файлы, которые предполагается создать или изменить.
5. Перечисли возможные риски и неясности.
6. Дождись подтверждения пользователя.

После подтверждения:

1. Выполни только согласованный план.
2. Не вноси посторонние изменения.
3. Проверь результат.
4. Выполни сборку и относящиеся к задаче тесты.
5. Предоставь отчёт о проделанной работе.

## 4. Работа с кодом

- Не изменяй архитектуру без согласования.
- Не удаляй существующий код без обоснования и разрешения.
- Не дублируй существующие классы и функциональность.
- Не добавляй сторонние библиотеки без необходимости и согласования.
- Соблюдай принципы SOLID там, где они действительно применимы.
- Предпочитай простые и понятные решения избыточным абстракциям.
- Не оставляй незавершённые реализации, заглушки и TODO без согласования.

## 5. Работа с документацией

- Документация и комментарии пишутся на русском языке.
- Документация должна соответствовать фактической реализации.
- Не изменяй согласованные требования без разрешения пользователя.
- Новые технические решения документируй после их согласования.
- Не считай предварительные предложения утверждёнными решениями.

## 6. Тестирование

- Новая функциональность должна сопровождаться тестами.
- Исправления ошибок должны сопровождаться тестами, проверяющими исправленное поведение.
- Не удаляй и не ослабляй тесты ради успешного прохождения сборки.
- Не утверждай, что задача выполнена успешно, если проверки не запускались.
- Сообщай обо всех ошибках и предупреждениях, которые не удалось устранить.

## 7. Git и безопасность

- Не выполняй `git push` без прямого разрешения пользователя.
- Не выполняй destructive-команды Git без согласования.
- Не удаляй пользовательские файлы и данные.
- Не записывай пароли, токены и другие секреты в исходный код или документацию.
- Не изменяй настройки окружения пользователя без разрешения.
- Сообщения коммитов пишутся на русском языке.
- В сообщениях коммитов используются отглагольные существительные, а не инфинитивы и не повелительное наклонение: «согласование», а не «согласовать».
- Правило распространяется на заголовок и все пункты сообщения коммита.

## 8. Отчёт о выполнении

В конце каждой задачи укажи:

- что сделано;
- какие файлы созданы или изменены;
- какие решения приняты;
- какие команды проверки выполнены;
- результаты сборки и тестирования;
- какие вопросы остались нерешёнными.
